Stack is the local cockpit for Synth research engineering. It gives one operator and one agent a single place to run local work, read hosted work, steer live work, and keep evidence without switching between repos, backend routes, SDK snippets, and browser pages. The product promise is local-first, hosted-aware, and receipt-driven:

1. A user can start locally without Synth auth.
2. A signed-in user can select dev, staging, or prod and see the hosted state that matters.
3. A subscribed user can opt actors into Synth inference with explicit controls and visible spend.
4. An engineering operator can run local GEPA, graduate to hosted GEPA, inspect artifacts, and keep the run ids.
5. A research operator can inspect SMR runs, WorkProducts, hosted artifacts, traces, and Factory state.
6. A cloud operator can attach to a typed DevEnvironment when the `.5` UI lands.

The invariant across every surface is a receipt spine: route owner, run id, project id, work product or artifact id, trace id when present, git SHA when present, cost or usage state when present, and the command or UI action that produced the evidence. Stack does not create a second ledger for any hosted system.

## Product Model

Stack has three operator profiles. Profiles are cockpit presets, not permissions:

| Profile | Promise | Default emphasis |
| --- | --- | --- |
| `engineering` | Build and debug local or hosted research-engineering flows quickly. | local GEPA, containers, doctor, artifact downloads |
| `research` | Observe and steer SMR, Factory, traces, hosted runs, and receipts. | remote projects, live runs, WorkProducts, hosted optimizers |
| `product` | Inspect product usage, funnel health, docs links, and launch receipts. | telemetry, releases, artifacts, summary prompts |

Profiles change prompts, skill availability hints, MCP tool allow/deny filters, default worker model/effort, and layout defaults. They do not grant backend rights. Backend rights still come from `SYNTH_API_KEY`, org membership, subscription plan, and owner-route authorization.

Stack's user-facing vocabulary is:

| Word | Meaning |
| --- | --- |
| `Profile` | Cockpit preset: research, engineering, or product. |
| `Environment` | Backend target: dev, staging, or prod. |
| `Run` | SMR or optimizer execution. |
| `Project` | Backend research project owner scope. |
| `WorkProduct` | Durable output generated by SMR or Factory. |
| `HostedArtifact` | Browser-openable artifact built from a WorkProduct or run. |
| `ContainerPool` | Hosted pool on the live `/v1/pools` surface. |
| `DevEnvironment` | Live cloud dev resource under `/smr/dev-environments`. |
| `EnvironmentManifest` | Immutable manifest catalog item under `/smr/environments`. |
| `Receipt` | Projection over work products, traces, git refs, cost, usage, and action metadata. |

## Install and Update Contract

Stack installs from the nightly channel at `stack.usesynth.ai/install.sh`. The install story is intentionally narrow:

| Operator state | Expected behavior |
| --- | --- |
| Fresh local user | Install Stack, start the cockpit, and run local-only flows without `SYNTH_API_KEY`. |
| Signed-in user | Add `SYNTH_API_KEY`, select `dev`, `staging`, or `prod`, and read hosted state through owner routes. |
| Subscribed org | Opt actors into Synth inference and see entitlement, usage, and cap state before or during use. |
| Updating user | Move to the next nightly dev cut; stable remains `0.1.0` until explicitly called. |

The installer must not write user-level Codex skills. Skills sync is workspace-local: `.codex/skills` plus Stack-owned `.stack/skills`. The updater must preserve `.stack/config/profile.json`, `.stack/downloads/`, and local evidence receipts.

## Architecture Rules

1. Backend owns hosted state and route contracts.
2. synth-ai owns Python SDK, CLI, and MCP client surfaces for Managed Research and DevEnvironments.
3. optimizers owns GEPA local service and hosted submit CLI behavior.
4. containers owns the container task HTTP contract.
5. Stack owns the local cockpit, TUI, stackd, MCP presentation, workspace skills, and local download state.
6. Stack may use narrow TypeScript remote wrappers while no JS SDK exists, but those wrappers mirror backend or synth-ai contracts. They must not mint fallback routes, scrape DB/Redis, or read compatibility projections.
7. No exception path may cross authority boundaries. A failure can add context, redact unsafe data, or fail loudly.
8. All hosted writes need a typed owner route and a receipt. No raw browser or object-store URL becomes the state owner.
9. Local `.stack/` and workspace `.codex/skills` are the writable homes. Stack never mutates a user's global `~/.codex` skills.
10. Nightly dev cuts are the shipping channel until the owner explicitly calls a stable/minor release.

## Surface 1: Inference

### Product Promise

Stack provides two Synth inference lanes:

| Lane | Product use | Model | Billing posture |
| --- | --- | --- | --- |
| `stack-aux` | Sidekick actors: monitor, gardener, aux. | `nemotron-3-ultra` | Promo/free aux lane with org and synth-wide caps. |
| `stack-inference` | Billed GLM lane for monitor, gardener, remote gardener, and explicitly opted-in worker. | `baseten/zai-org/GLM-5.2` | Subscription-gated for worker roles; capped by org and synth-wide daily spend. |

The local worker default remains BYOK/ChatGPT/Cursor through the chosen agent CLI. Worker-on-Synth is explicit: `STACK_SYNTH_WORKER_INFERENCE=1` makes Stack generate Codex provider config for the Responses proxy. Stack never silently routes a worker to billed Synth inference.

### Technical Contract

| Contract | Authority |
| --- | --- |
| Free aux route | `POST /api/v1/stack-aux/openai/v1/responses` in `backend/app/api/public/stack_aux/openai_routes.py` |
| Billed inference route | `POST /api/v1/stack-inference/openai/v1/responses` in the same file |
| Model aliases | `backend/app/api/public/stack_aux/aliases.py` |
| Actor policy | `backend/app/api/public/stack_aux/policy.py` |
| Usage route | `GET /api/v1/stack-inference/usage` and `GET /api/v1/stack-aux/usage` |
| Stack catalog/read side | `stack/src/remote/inference.ts`, `stack/src/remote/usage.ts`, `stack/src/config.ts` |

Auth is `SYNTH_API_KEY`. The request is OpenAI Responses wire format. Stack sets `X-Stack-Actor-Role`. Worker roles also require `X-Stack-Worker-Opt-In` or `X-Stack-Synth-Inference-Opt-In` to be truthy. Codex custom provider config uses:

```text
base_url = <apiBaseUrl>/api/v1/stack-inference/openai/v1
wire_api = responses
env_key = SYNTH_API_KEY
X-Stack-Actor-Role = worker
X-Stack-Worker-Opt-In = explicit
```

Guard errors set the pattern for all Stack remote gates:

| HTTP | Code | Meaning | Operator action |
| --- | --- | --- | --- |
| 402 | `stack_inference_worker_requires_subscription` | Worker role lacks `standard` or `max` plan. | Upgrade or run local/BYOK worker. |
| 429 | spend-cap code in response detail | Org or synth-wide daily billed lane cap hit. | Wait for reset or owner raises cap. |
| 503 | plan lookup failure for worker role | Entitlement cannot be proven. | Treat as fail-closed; retry after backend/billing recovery. |
| 400 | actor/model validation detail | Header or model alias is invalid. | Fix Stack config/provider config. |

### Client Ownership Ruling

The current Stack TypeScript wrapper directly calls backend usage and catalog routes. That is acceptable for the shipped TUI because no JS SDK exists. The Python SDK should still own the public typed client contract. The unmerged `wip/sdk-stack-aux-client-20260702` branch should be reviewed and landed or replaced by an equivalent `synth-ai` inference client so scripts, MCP, and external users do not copy Stack's TypeScript route logic.

## Surface 2: Optimizer Jobs

### Product Promise

Stack makes optimizer work concrete:

1. Run local GEPA from a TOML config and see the job in Local Research.
2. Graduate the same task/container setup to hosted GEPA.
3. Observe hosted status, frontier/result keys, events, artifact names, and terminal reason.
4. Preview or download hosted artifacts into Stack download state.
5. Keep both local and hosted run ids in handoffs.

Smoke-tier optimizer runs prove plumbing, not model improvement. A prompt-lift claim requires a gate-sized profile and acceptance evidence.

### Technical Contract

| Mode | Route or command | Authority |
| --- | --- | --- |
| Local service | `synth-optimizers gepa service --db ... --bind 127.0.0.1:8879` | `optimizers` repo |
| Local submit | `POST /runs` JSON run request | `optimizers` service contract |
| Hosted submit | `synth-optimizers gepa submit --config ... --tunnel-provider synth_tunnel` | `optimizers` source checkout |
| Tunnel | SynthTunnel lease | `synth_ai/sdk/tunnels.py` |
| Hosted list/detail | `/api/v1/optimizers/runs`, `/api/v1/optimizers/runs/{run_id}` | backend |
| Hosted artifacts | `/api/v1/optimizers/runs/{run_id}/artifacts/{artifact_name}` | backend |
| Stack local wrapper | `stack_launch_gepa` | `stack/src/local/optimizers.ts`, `stack/src/mcp/server.ts` |
| Stack hosted wrapper | `stack_submit_hosted_optimizer` | `stack/src/remote/optimizers.ts`, `stack/src/mcp/server.ts` |
| Stack artifact wrappers | preview/download hosted optimizer artifact | `stack/src/remote/optimizers.ts` |

Hosted submit must resolve the source checkout when the PATH `synth-optimizers` install lacks `gepa submit`. Stack implements this by preflighting the configured command and falling back to `uv run --project <optimizers checkout> synth-optimizers ...`.

Hosted SynthTunnel runs must use a hosted-safe TOML:

```text
output_dir = "runs"
[container]
# no local command, cwd, or URL; SynthTunnel is the container authority
```

Local proof TOMLs with host absolute `output_dir`, `container.command`, `container.cwd`, or a localhost `container.url` can fail hosted execution with opaque filesystem errors. Stack should add preflight diagnostics for this class before accepting a hosted submit.

### Artifact Names Ruling

Backend successful hosted optimizer payloads can advertise artifacts under `result.artifact_handles`, root `artifact_handles`, state `artifact_handles`, or artifact arrays. Stack must read all of these. The shipped fix is in `stack/src/remote/optimizers.ts` and landed in `0.2.0-dev.20260702.4`.

## Surface 3: Containers

### Product Promise

Stack gives agents the container skills and just enough tools to discover pools, check health, run bounded rollouts, and follow traces/artifacts. The product is not a container admin console. It is a path from a task app to a rollout receipt.

### Technical Contract

The live backend container surface is `/v1/pools` plus `/v1/rollouts`.

| Operation | Route |
| --- | --- |
| List/create/update/delete pools | `/v1/pools`, `/v1/pools/{pool_id}` |
| Pool URLs | `/v1/pools/{pool_id}/urls` |
| Container health | `/v1/pools/{pool_id}/container/health` |
| Task-scoped health | `/v1/pools/{pool_id}/tasks/{task_id}/container/health` |
| Container info/task_info/metadata/program/taskset | `/v1/pools/{pool_id}/container/...` |
| Synchronous container rollout | `/v1/pools/{pool_id}/container/rollout` |
| Task-scoped rollout | `/v1/pools/{pool_id}/tasks/{task_id}/container/rollout` |
| Rollout events/artifacts/usage/summary/support bundle | `/v1/rollouts/{rollout_id}/...` and pool-scoped equivalents |

Stack wrappers are `stack_list_container_pools`, `stack_container_health`, and `stack_container_rollout`. They pass container-native JSON request bodies through unchanged and redact signed object-store URLs from backend errors before returning MCP payloads.

### Client Ownership Ruling

`synth-ai/synth_ai/sdk/containers.py` still points at `/v1/containers`, which is not the live backend route. The canonical hosted route is `/v1/pools`. The SDK must either:

1. deprecate `containers.py` and make `pools.py` the only public hosted container client, or
2. make `containers.py` a compatibility facade over `/v1/pools`.

Stack must not build new logic on `/v1/containers`.

## Surface 4: Hosted Artifacts and WorkProducts

### Product Promise

Stack lets an agent discover outputs, preview bounded text, download durable files, and open hosted pages in a browser. Artifacts are evidence, not decoration. Every download lands under Stack state and should be cited with a run id or artifact id.

### Technical Contract

| Operation | Route | Stack tool |
| --- | --- | --- |
| List org hosted artifacts | `GET /smr/hosted-artifacts` | `stack_list_hosted_artifacts` |
| List project hosted artifacts | `GET /smr/projects/{project_id}/hosted-artifacts` | `stack_list_hosted_artifacts` |

## Surface 6: Cloud DevEnvironments

### Product Promise

DevEnvironments make Stack an SSH-style cockpit for cloud Synth-on-Synth work. The operator promise is:

1. Create or attach to a project-scoped cloud dev environment.
2. Deploy a typed `synth-dev` topology into Daytona first.
3. Bind repo, branch, context packet, and scorecard.
4. Launch Factory/SMR work in that environment without using the laptop as the runtime.
5. Observe services, logs, runs, receipts, git refs, cost, and traces from Stack.

The claim is evaluatable cloud dev work with receipts. It is not a browser IDE, not generic BYOC, and not an optimizer-quality claim until acceptance evidence exists.

### Technical Contract

Backend route home is `/smr/dev-environments`. It is distinct from immutable `/smr/environments`.

| Operation | Route |
| --- | --- |
| List/create live environments | `GET/POST /smr/dev-environments` |
| List/get topologies | `GET /smr/dev-environments/topologies`, `GET /smr/dev-environments/topologies/{topology_id}` |
| Materialization queue | `GET /smr/dev-environments/materialization-queue` |
| Get live environment | `GET /smr/dev-environments/{dev_environment_id}` |
| Claim materialization | `POST /smr/dev-environments/{dev_environment_id}/materialization-lease` |
| Preflight | `POST /smr/dev-environments/{dev_environment_id}/preflight` |
| Deploy/start/stop/snapshot | `POST /smr/dev-environments/{id}/deploy`, `/start`, `/stop`, `/snapshot` |
| Materialization report | `POST /smr/dev-environments/{id}/materialization` |
| Destroy | `DELETE /smr/dev-environments/{id}` |
| Read services/attach/logs/runs/usage/receipts | `GET /smr/dev-environments/{id}/...` |

Core models are in `backend/app/api/v1/managed_research/dev_environments.py` and persistence in `backend/services/smr/persistence/dev_environments.py`. A DevEnvironment response has `dev_environment_id`, `environment_id` alias, org/project, name, backend target, `lifecycle_state`, topology id/version, environment manifest name/digest, `host_kind`, quota class, cost summary, service summary, metadata, and timestamps.

synth-ai owns the typed client:

| Layer | File |
| --- | --- |
| SDK namespace | `synth_ai/managed_research/sdk/dev_environments.py` |
| Raw client methods | `synth_ai/managed_research/sdk/client.py` |
| CLI | `synth_ai/cli/dev_envs.py` |
| MCP tools | `synth_ai/managed_research/mcp/tools/dev_environments.py` |
| Run binding | `synth_ai/managed_research/sdk/runs.py` |

Stack must use synth-ai or Stack MCP for this surface when the Stack UX lands. It must not implement separate raw HTTP behavior for DevEnvironment lifecycle.

### Rulings

1. `DevEnvironment` is the live lifecycle resource.
2. `EnvironmentManifest` remains the immutable image/secret/repo/mount catalog item.
3. `EnvironmentTopology` points at `/smr/environments`; it is not a second image authority.
4. Daytona is the first substrate. Railway sandboxes are second.
5. Receipts are projections over WorkProducts, traces, git refs, and cost rows. There is no second receipt table.
6. Cloud launch mode is `dev_slot_execution`. It must not silently downgrade to local execution.

## Surface 7: Research Flywheel Tools

### Product Promise

The `.6` line prepares Stack for human calibration sessions on Banking77, Craftax, and Harvey lab. The product promise is the full local to cloud loop, not just optimizer launch:

1. Edit harness or prompt locally.
2. Run local evaluation or local GEPA.
3. Push context or artifacts to a hosted run when the task allows it.
4. Watch long hosted work without manual polling.
5. Pull champion artifacts back into the workspace.
6. Apply a champion prompt or related artifact to a local harness config.
7. Run final evaluation locally and keep every receipt.
8. Capture friction during the run without leaving the cockpit.

Stack stays thin in this surface. GEPA, GELO, Tinker, SMR, containers, and StackEval own execution and scoring. Stack owns launch/read ergonomics, artifact synchronization, local apply mechanics, and receipts.

### Technical Contract

The `.6` branch adds four local Stack capabilities. They are not part of the published `0.2.0-dev.20260702.4` nightly until the next cut.

| Capability | Contract | Files |
| --- | --- | --- |
| Artifact pull/apply/push | MCP tools `stack_pull_artifact`, `stack_apply_artifact`, and `stack_push_artifact`; typed artifact kinds `champion_prompt`, `adapter_weights`, `dataset`, `eval_table`; receipts under `.stack/evidence/roundtrip/` with schema `stack.roundtrip.receipt.v1` | `stack/src/roundtrip.ts`, `stack/src/mcp/server.ts` |
| Hosted optimizer watch | TUI watch section over existing hosted optimizer detail and usage snapshots; no backend route added | `stack/src/tui/hosted-watch.ts`, `stack/src/tui/app.ts`, `stack/src/remote/optimizers.ts` |
| Task doctor | `stack doctor --task <toml>` parses generic task TOML and emits pass/warn/fail rows with `auth`, `quota`, `config`, or `transient` classes where relevant | `stack/src/task-doctor.ts`, `stack/src/doctor.ts`, `stack/src/main.ts` |
| Papercut capture | TUI capture writes timestamped run-context records under Stack guidance state | `stack/src/papercut-capture.ts`, `stack/src/tui/app.ts` |

Roundtrip pull reads from hosted optimizer artifacts, saved downloads, or local files. It writes the workspace artifact plus a receipt containing the backend environment, API base URL, run id, project id when known, artifact name or output id, source path, workspace path, SHA-256 digest, git SHA at pull time when available, and timestamp. Apply currently supports `champion_prompt` into TOML string fields, defaulting to `seed_candidate.stage2_system`, or replacing a file. Push uses the existing SMR run-file owner route and records a push receipt; it does not invent a second upload surface.

Task doctor is deliberately generic. It checks declared files, harness templates, harness/container commands, API-key env references, backend reachability, Synth auth, subscription/cap readability, optimizer CLI, local optimizer service/port, declared container image, live container health when a URL exists, service port declaration/free state, tunnel inputs, and private-lane conflicts. It must not hard-code Banking77, Craftax, Harvey, or StackEval semantics.

Papercut capture writes local guidance records, not global Jstack bug records. The line is grep-stable and includes source, environment, profile, focus, task id, run id, project id, optimizer run id, factory id, artifact id, thread id, and meta thread id when those are known.

## Cross-Surface Error Model

Stack remote surfaces should present backend errors in a common envelope:

| Field | Meaning |
| --- | --- |
| `ok` | Boolean success. |
| `status` | HTTP status or process exit status. |
| `code` | Stable backend or Stack error code when present. |
| `message` | Operator-safe summary. |
| `environment` | `dev`, `staging`, or `prod`. |
| `route_owner` | backend, synth-ai, optimizers, containers, or stackd. |
| `next_action` | Concrete owner or operator action when known. |

The guard codes from inference are the model:

| Class | HTTP | Example |
| --- | --- | --- |
| Entitlement | 402 | Worker Synth inference requires `standard` or `max`. |
| Budget/capacity | 429 | Daily spend cap or rollout concurrency limit. |
| Owner unavailable | 503 | Plan lookup failed, hosted runtime unavailable. |
| Contract mismatch | 400 or 422 | Missing actor role, bad rollout payload, invalid DevEnvironment state. |
| Missing resource | 404 | Hosted artifact absent, WorkProduct absent, pool archive missing. |
| Backend defect | 500 | Runtime image missing module, stale migration, object-store inconsistency. |

Stack must redact signed object-store URLs, account ids, account labels, account emails, and claim references before returning MCP diagnostics.
